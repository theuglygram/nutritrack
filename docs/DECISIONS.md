# NutriTrack — Architectural Decisions

To change an accepted decision, add a new entry that supersedes it; do not edit history.

---

## Accepted — from the project brief

| ID      | Decision                                                                                                                        | Reason                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| ADR-001 | Monorepo managed with **pnpm** workspaces                                                                                       | One repo for web, mobile and shared logic; pnpm is fast and strict about dependencies     |
| ADR-002 | Web: **Next.js, TypeScript, Tailwind CSS, shadcn/ui**                                                                           | Server rendering; accessible component primitives                                         |
| ADR-003 | Mobile: **React Native, Expo, Expo Router**, TypeScript                                                                         | One codebase for Android and iOS; shares TS logic with web                                |
| ADR-004 | Backend: **Supabase** (Postgres, Auth, Storage)                                                                                 | Managed Postgres with RLS, auth and storage in one platform                               |
| ADR-005 | Validation: **Zod**, shared between client and server                                                                           | One schema definition for forms, APIs and AI output validation                            |
| ADR-006 | Nutrition calculations are **deterministic code in a shared package**, never LLM-generated                                      | Accuracy, testability, identical results on every platform                                |
| ADR-007 | AI identifications and portions are **suggestions requiring user edit/confirm**                                                 | AI is error-prone; users own their data                                                   |
| ADR-008 | **RLS on all user-owned data**; schema changes **only via migrations**                                                          | Security by default; reproducible database                                                |
| ADR-009 | Service-role and AI keys **server-only**                                                                                        | Prevent key leakage from web bundles or mobile apps                                       |
| ADR-010 | Charts on web: **Recharts**                                                                                                     | Specified in brief                                                                        |
| ADR-011 | Logged items store a **nutrient snapshot**; serving-unit gram weights are **per food**; unknown nutrients are **null, never 0** | Catalogue corrections must not rewrite history; a wrap of eba ≠ a wrap of amala; accuracy |

## Accepted — approved by project owner on 2026-11-10

| ID            | Decision                                                                                                                                                                                                                                                                                   | Reason                                                                                                                                                                                             | Follow-up required                                                                                  |

| ADR-012 (O01) | AI provider: **Anthropic Claude** — Haiku 5.5 for text parsing; Sonnet 5.5 for photo recognition and the assistant — behind a **provider-agnostic server interface**                                                                                                                       | Strong vision and structured output; interface keeps the provider swappable                                                                                                                        | Benchmark against one alternative (e.g. Gemini) on the Nigerian dish test set before Stage 11 ships |
| ADR-013 (O02) | Food data: **FAO/INFOODS West African Food Composition Table** as primary, plus published Nigerian food composition tables; composite dishes **calculated from recipes**; serving sizes **measured by weighing real portions**; a **qualified Nigerian dietitian** signs off verified data | Traceable sources; local accuracy                                                                                                                                                                  | Check each source's licence for commercial use; engage the dietitian before Stage 04                |
| ADR-014 (O03) | Task runner: **Turborepo**                                                                                                                                                                                                                                                                 | Cached builds/tests across apps with little setup                                                                                                                                                  | —                                                                                                   |
| ADR-015 (O04) | Mobile charts: **react-native-gifted-charts**                                                                                                                                                                                                                                              | Simple charts; fewer native dependencies and smaller app than Skia-based options                                                                                                                   | —                                                                                                   |
| ADR-016 (O05) | Admin dashboard: **route group inside `apps/web`** (`/admin`), enforced by RLS and server checks                                                                                                                                                                                           | Reuses auth, components and deploy; split later if needed                                                                                                                                          | —                                                                                                   |
| ADR-017 (O06) | Shared server logic in **Supabase Edge Functions**; Next.js server used only for web rendering and web-only concerns                                                                                                                                                                       | Mobile and web call the same endpoints without depending on the web app                                                                                                                            | `packages/core` and `packages/schemas` must stay pure TS and Deno-compatible                        |
| ADR-018 (O07) | **Queue-and-sync offline logging** on mobile for food, water and weight logs; records use **client-generated UUIDs**                                                                                                                                                                       | Unreliable connectivity; idempotent sync                                                                                                                                                           | Full offline food search deferred                                                                   |
| ADR-019 (O08) | **Freemium**: all tracking free; AI features rate-limited on free tier; **Paystack** for web payments; **app-store billing** for in-app subscriptions, unified via **RevenueCat**                                                                                                          | Core value free; AI has per-request cost                                                                                                                                                           | Pricing and exact free-tier limits to be set by project owner before AI features ship               |
| ADR-020 (O09) | **Metric only**; **English UI** at launch; search supports Yoruba, Igbo, Hausa and Pidgin food names                                                                                                                                                                                       | Nigeria uses metric; local names matter most in search                                                                                                                                             | Pidgin UI considered later                                                                          |
| ADR-021 (O10) | Treat health data as **sensitive personal data under NDPA 2023**: explicit consent at sign-up, account deletion and data export, meal photos **auto-deleted after 30 days**, photos used for evaluation **only with opt-in**                                                               | Legal and trust requirements                                                                                                                                                                       | **Nigerian data-protection lawyer review** before public launch                                     |
| ADR-022 (O11) | Hosting: **Vercel** (web), **EAS** (mobile builds and OTA updates), **Supabase CLI locally** + separate **staging** and **production** Supabase projects                                                                                                                                   | Standard for this stack                                                                                                                                                                            | Measure Lagos latency to candidate Supabase regions before creating projects                        |
| ADR-023 (O12) | Testing: **Vitest** (unit), **Playwright** (web E2E), **Maestro** (mobile E2E)                                                                                                                                                                                                             | Simple, Expo-friendly                                                                                                                                                                              | —                                                                                                   |
| ADR-024 (O13) | Targets: **Mifflin–St Jeor BMR × activity factor**; calorie floor **1,200 kcal (female) / 1,500 kcal (male)**; max loss **~1% body weight/week**; gain **0.25–0.5 kg/week**; protein **1.6 g/kg** for muscle-gain goals; default water **2.5 L**                                           | Widely used guideline values                                                                                                                                                                       | **Dietitian sign-off** before Stage 03 ships; values live as constants in `packages/core`           |
| ADR-025 (O14) | Auth: **email/password, Google and Apple** sign-in                                                                                                                                                                                                                                         | Apple sign-in generally required on iOS when Google is offered                                                                                                                                     | Phone OTP considered later (SMS cost)                                                               |
| ADR-026 (O15) | **Release 1:** onboarding, food database, manual and text logging, dashboard, weight, water, admin food management. **Release 2:** AI photo recognition with portion estimation, AI assistant                                                                                              | Photo recognition depends on a solid food database                                                                                                                                                 | Development plan reordered accordingly                                                              |
| ADR-028       | Stage 01 tooling: **TypeScript 6.0** (Expo SDK 58 pin) and **ESLint 9** repo-wide via pnpm catalog; shared packages export **TS source** (no build); shadcn/ui on **Base UI** primitives (`base-nova` preset)                                                                              | One version of each tool; ESLint 10 blocked by eslint-config-next's plugins; no build step keeps packages Deno-compatible                                                                          | Move to ESLint 10 when eslint-plugin-react / jsx-a11y / import support it                           |
| ADR-029       | **Food log entries stand alone** (date + meal slot on each entry, no parent meal row), and the **database computes the nutrient snapshot** by trigger from food, unit and quantity; client-supplied values are overwritten                                                                 | Offline devices can sync without conflicting on a shared parent; every write path (web, mobile, sync, Edge Functions) gets the same deterministic result; numeric rounding matches `packages/core` | Both test suites assert the same worked examples                                                    |
| ADR-030       | Database security tested with **pgTAP** (`supabase test db`) in a CI `database` job; generated types checked for drift; `packages/api-client` deferred to **Stage 03**                                                                                                                     | Proves RLS with simulated users on every push; the client setup depends on how auth stores sessions                                                                                                | —                                                                                                   |
| ADR-027 (O16) | **Sentry** (errors) and **PostHog** (product analytics)                                                                                                                                                                                                                                    | Support Next.js and Expo; free tiers                                                                                                                                                               | —                                                                                                   |

# NutriTrack — Architectural Decisions

To change an accepted decision, add a new entry that supersedes it; do not edit history.

## Accepted — from the project brief

| ID      | Decision                                                                                                                        | Reason                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| ADR-001 | Monorepo managed with **pnpm** workspaces                                                                                       | One repo for web, mobile and shared logic; pnpm is fast and strict about dependencies     |
| ADR-002 | Web: **Next.js, TypeScript, Tailwind CSS, shadcn/ui**                                                                           | Server rendering; accessible component primitives                                         |
| ADR-003 | Mobile: **React Native, Expo, Expo Router**, TypeScript                                                                         | One codebase for Android and iOS; shares TS logic with web                                |
| ADR-004 | Backend: **Supabase** (Postgres, Auth, Storage)                                                                                 | Managed Postgres with RLS, auth and storage in one platform                               |
| ADR-005 | Validation: **Zod**, shared between client and server                                                                           | One schema definition for forms, APIs and AI output validation                            |
| ADR-006 | Nutrition calculations are **deterministic code in a shared package**, never LLM-generated                                      | Accuracy, testability, identical results on every platform                                |
| ADR-007 | AI identifications and portions are **suggestions requiring user edit/confirm**                                                 | AI is error-prone; users own their data                                                   |
| ADR-008 | **RLS on all user-owned data**; schema changes **only via migrations**                                                          | Security by default; reproducible database                                                |
| ADR-009 | Service-role and AI keys **server-only**                                                                                        | Prevent key leakage from web bundles or mobile apps                                       |
| ADR-010 | Charts on web: **Recharts**                                                                                                     | Specified in brief                                                                        |
| ADR-011 | Logged items store a **nutrient snapshot**; serving-unit gram weights are **per food**; unknown nutrients are **null, never 0** | Catalogue corrections must not rewrite history; a wrap of eba ≠ a wrap of amala; accuracy |

| ADR-033       | **Public landing page and app dashboard** (approved 2026-11-10, between Stages 03 and 04). Web: `/` is a static public landing page; the signed-in dashboard moves to `/home`; signed-in visitors to `/` go to `/home`; `/settings` becomes `/profile` (old URL redirects). Five destinations on both platforms (**Home, Food, Scan, Progress, Profile**): a left sidebar on web at 1024 px and wider, a bottom bar on web phones, and Expo Router tabs on mobile. **Brand tokens** (forest green, cream, lime, charcoal; Bricolage Grotesque + Inter) live in `packages/core/src/brand.ts`; web mirrors them as CSS variables, checked by a test. **Water and weight entry pulled forward from Stage 07** (tables and RLS already existed). Unbuilt features (food logging, photo scan, AI insights) are **shown disabled and labelled "Coming soon"**, never as working. The insight card is a **rule-based note** from `packages/core` (`dailyTip`), labelled as not AI, and never names foods. Food imagery is **illustrated** until licensed photos are supplied. New deps: `recharts` (web, already approved), `react-native-svg`, `lucide-react-native`, `expo-font` + Google font packages (mobile) | Visitors need to know what NutriTrack is before signing up; a real dashboard exercises targets, water and weight end to end; honest labels avoid claiming unbuilt features; one token source keeps platforms consistent | Mobile charts use **react-native-svg directly** for now (one small trend line); adopt react-native-gifted-charts (ADR-015) with the Stage 06 charts.
